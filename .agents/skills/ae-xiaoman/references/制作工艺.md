# AE 小漫制作工艺

[打开《皇帝的新装》正式成品样例：交付 ZIP、开篇试听和逐页文本](../../../../制作样例/皇帝的新装/README.md)。

适用于常规线性有声绘本。制作、文本和审听同事共用本页；具体书名、年龄档和现行稿以仓库首页的共享领稿表为准。

## 文本与单集长度

| 项目 | 执行口径 |
|---|---|
| 年龄 | 按 3–6、7–10、11–12、13–16 岁之一立项。低龄稿用能看见的动作讲因果，高龄稿给动机、矛盾和选择留篇幅。 |
| 材料 | 保存可追溯的公版英文全文、独立中文全译、逐页绘本稿、中文发行版本对读。对读注明查阅范围、删改与新增，区分已读正文和只查到书目。 |
| 篇幅 | 精品单本先按约 30 页正文、约 6–8 分钟设计，另设独立作品页。参照《皇帝的新装》32 页正文、1,176 个正文汉字、定稿 6 分 07 秒。以情节、年龄和听感决定实际长度。若短，先查漏掉的行动、转折和结果；只有故事需要时才扩写。 |
| 单页 | 交付 JSON 的每页 text 含标点最多 50 个显示字符。每页留下一个清楚的动作、发现或回应。按意群断页，代词、指向和时间顺序读得通。 |
| 首尾 | 作品页报完整书名；正文前两页交代谁、身在何处或遇到什么、为何行动。结尾交代行动的后果，以可感知的动作、声音或画面收住。 |

### 锁稿前怎样审结尾

文本负责人把正文前两页与最后几页放在一起读，在该书审读记录写下两句话：开头让孩子惦记什么？末页哪个动作、物件或回答让孩子知道这件事有了结果？注明对应页码。结尾可以让人继续想，听众仍应明白本书讲的那件事已经走到了哪里。

- **连续举例的故事**。试着在末页后接“隔壁还有一只……”。如果接上去跟前几页同样顺，就回看这一串例子合在一起说明了什么。可以把视线从最后一个角色稍稍拉远，再落回一个已经铺垫过的细节。《喜鹊教搭窝》里，每只鸟在不同步骤离开，才有了各不相同的窝；椋鸟叼走的白羽毛让这个结果摸得着。
- **人物作出选择的故事**。找一个只有经历了前面的事才有意味的动作。《皇帝的新装》里，街上的人都说出了真相，侍从的手却又端了起来。孩子知道那条衣摆根本不存在，手势本身就能收尾。
- **交给另一位审读者试读**。隐去页码和结束提示，自然读完最后几页，问“你觉得停在哪一句正好？为什么？”如果回答只是“天黑了”“音乐停了”，或者听者还在等同一串里的下一件事，先回到正文找所缺的结果。低龄稿用孩子能指给人看的东西表达，高龄稿可以把对人物的判断留给读者。
- 文本审读记下实际版本、末句和判断依据。制作窗口再按同版连听倒数几页，核对关键字是否清楚、末句是否落稳、最后一个动作听完能否停下。两次判断分别回填，附加静音的长度不能代替听审。

## 旁白、对白与音效

默认旁白为 **R02 醇实爽朗女声**。使用团队已采用的 R02 原速参考及对应配置；本地 Qwen 克隆流程从原速参考解码，保留音高与速度。项目另指定 SeedAudio 原声时，沿用该书已确认的短样。新电脑从项目管理人取得获准使用的参考音、配置和相应工具权限；本仓库提供方法与文本，音色文件和服务账号另行交接。

慢读要让孩子听清谁在做什么。初次试音可参考已确认短样约 **166 汉字/分钟**（40 秒连续讲述，含句内停连）。记录时说明分母是朗读段还是整本含留白。先按自然语气说完整个意群；动作连续时顺势往下讲，反转、发现或观察画面时才多留一点时间。报书名一口气说完整，在词组重心上着力。旁白引出人物后，对白及时接上；用声音的远近、轻重和角色意图区分说话人。固定给标点补静音会把已有换气和翻页停留叠在一起。

先交一段包括旁白、对白、翻页的连续试听。语义相连的页一起生成，再按实测时间轴切页，核对每页首尾字。音效贴动作或环境变化，人物开口时给人声留空间；结束后回听最后一句与收尾留白。

**最终设备音量**以《北风和太阳》中档复测 R4 为基准。对已混好音效、编码后的逐页 MP3 按页码拼接解码，整本综合响度目标 **−12.72 LUFS，容差 ±0.5 LU**；逐页实测最高真峰值 **≤ −1.0 dBTP**。依据各书原录音调增益并限峰，保留轻声与重读。真机以同一台设备、同一档位对听。

## 画面和双端交付

书架封面横版 **200×150**，画面铺满，主体、四肢和关键道具完整。作品页是书内第 001 页，使用 **340×400** 竖版画面。书名与插画同次生成，系列沿用清晰厚实的手绘字，标题颜色从本书画面取色。黑白版核对字形、线条与主体辨识度。逐页检查角色、动作、道具状态与本页文字对应。

单本 ZIP 顶层直接放确定的作品编码目录。以下取自已验收格式；省略号表示后续页沿用相同编号方式。

~~~text
huangdidexinzhuang_7_10_AE11/
  meta.json
  pages.json
  cover.png                 AE11 黑白
  cover_200150.png          AE30 彩色
  pages/
    001.png                 AE11 黑白，340×400
    001_340400.png          AE30 彩色，340×400
    001.mp3                 双端共用，同页朗读
    …
~~~

meta.json 使用 version、title、subtitle、typeCode、minAge、maxAge、intro、rewardClaimMode，沿用已确认模板。已交付示例使用版本字符串 "1.0"、奖励模式 "ONCE" 和整数年龄。typeCode 取目标后台已启用的编码，常用 adventure、fairyTale、science、comedy，大小写须一致。文学体裁可另在项目书目登记。

pages.json 是数组。第 001 页的 tocTitle 填 meta.title，text 为报幕书名；后续真实章首或目录入口保留标题，同章其余页填空字符串。仅在第 2 页重复出现的书名清空该页 tocTitle。两个真实条目的写法如下：

~~~json
[
  {"pageNo": 1, "tocTitle": "皇帝的新装", "text": "皇帝的新装"},
  {"pageNo": 2, "tocTitle": "皇帝又在换衣", "text": "皇帝每天换好多回衣服。早晨进一趟更衣室，过一会儿又进去一趟。侍从索性让门一天到晚敞着。"}
]
~~~

作品共 N 页时，书内有 2 份 JSON、2 张封面、N 套图图音，共 4＋3N 个文件。页码从 1 连续到 N，文件名用三位编号。多本按 1/、2/、3/ 分组，每组最多 10 个完整作品目录。最终重新打开 ZIP，按 pages.json 逐页解码音频并核对时长和响度，检查每张图片尺寸、每屏文字、目录跳转、连续播放及末页停留。交付清单写明采用的稿版、总页数、成品时长、实测响度、文件位置和待审项。
